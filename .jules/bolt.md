## 2024-06-04 - Concurrent Content Fetching in Aggregation Service
**Learning:** In the `ContentAggregationService`, fetching content from multiple platforms (YouTube, Instagram, TikTok, Facebook) was done sequentially using a `for` loop with `await`. Since each platform fetch introduces simulated network latency (e.g., YouTube 500ms, Facebook 600ms), sequential awaiting created a performance bottleneck, causing total latency to scale linearly with the number of connected platforms. This is an anti-pattern for independent network requests.
**Action:** Replaced sequential `await`s with concurrent fetching using `Future.wait`. We map over the connections to create a list of futures, each handling its own error via `.catchError`, and then await all of them simultaneously. This reduces the total network latency to the maximum latency of the slowest individual platform, significantly improving content aggregation speed. Note that `.toList()` must be called on the mapped iterable to ensure eager execution before passing to `Future.wait`.
