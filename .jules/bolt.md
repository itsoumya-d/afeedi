## 2024-05-24 - [Dart Future.wait Concurrent Execution and Error Handling]
**Learning:** In Dart, using `.map()` to create an iterable of asynchronous operations for `Future.wait()` evaluates lazily unless `.toList()` is called, preventing true concurrency. Furthermore, when returning a Future from a try-catch block (like inside an async map callback), `return await` is required to catch exceptions locally; otherwise, exceptions bubble up, bypassing local error tracking (like asynchronous `AnalyticsService.instance.trackError`) and aborting the entire `Future.wait()`.
**Action:** Always append `.toList()` to eagerly evaluate iterable futures for concurrent execution, and ensure `return await` is used inside try-catch blocks of async map callbacks to prevent a single platform's error from failing the entire aggregation.
